## 1. 范围与产品决策

规模约束：用户确认目前约 100 人，预计不超过 200 人。优先日常录入便利、清晰样式和简单维护；沿用现有技术栈，500 条输入上限仅保留为既有保护边界。

| 模块 | 管理对象 | 主要操作 |
|---|---|---|
| 培训考勤 | 一次培训及其参加名单 | 创建场次、编辑信息、粘贴校验、搜索添加、补录、移除与恢复 |
| 普通标签 | 服务记录的分类及标签关联 | 配置标签组与标签、设置适用服务项、添加与解除关联、查看对应记录 |

- 培训考勤使用独立场次，不再通过普通标签的挂接、取消挂接维护受训名单。
- 普通标签保留分类功能，关联列表只维护关联，不批量创建、修改或删除服务记录。
- 页面使用业务名称，不再展示 `managed / tag_only / openness` 等内部配置词。
- 本轮复用现有志愿者、服务项、个人记录和统计体系，不引入新的账号权限等级。
- 不增加签到二维码、请假审批、课程排期或自动按规则批量贴标签等未讨论功能。

## 2. 培训考勤

### 2.1 页面与场次信息

按用户最新反馈优化布局：桌面左侧为场次导航，右侧顶部为紧凑培训摘要，下方将人员录入与当前名单并排放置。录入区通过“粘贴名单／搜索添加”切换，共用待加入名单；手机依次展示摘要、录入区、当前名单，避免横向挤压。

- 场次列表展示名称、日期、类型和有效参加人数，支持按名称搜索、日期筛选。
- 新建场次填写名称、类型、时长、内容、日期，可以先保存空名单，之后继续录入。
- 类型对应现有 `TRAINING_ATTENDANCE` 受训服务项；与组织培训所产生的 `PROJECT_TRAINING` 志愿服务记录区分。
- 时长沿用现有规则：大于 0，以 0.5 小时为步长；日期按业务日期处理，避免浏览器时区改变日期。
- 场次信息与名单录入分开保存，补录人员不要求重新填写培训信息。
- 当前名单展示姓名、志愿者 ID、部门及有效人数，支持搜索；点击姓名进入志愿者主页。

### 2.2 粘贴名单与校验

流程：粘贴名单 → 自动校验并展示结果 → 处理重名或错误 → 确认加入名单。

- 延续现有纯姓名单列粘贴，接受换行、逗号、顿号、分号及制表符分隔；兼容现有志愿者编号（如 `PG-0001`）。内部稳定 Volunteer ID 用于去重和提交，不要求用户手工输入。
- 优先按志愿者 ID 匹配；姓名匹配支持现有中文名、英文名，重名时要求选择具体人员。
- 名单解析由服务端提供统一结果；前端预览与实际保存使用相同规则，避免预览成功、提交失败的口径差异。

| 校验结果 | 界面行为 | 保存行为 |
|---|---|---|
| 可新增 | 展示匹配到的姓名、ID、部门 | 加入待确认名单 |
| 当前名单已有 | 标记“已在名单中” | 跳过，不重复录入 |
| 本次输入重复 | 标明对应重复人员 | 仅保留一次有效新增 |
| 未匹配或不可录入 | 保留原输入并说明原因 | 修正前不加入 |
| 重名待选择 | 展示候选人的 ID、部门 | 明确选择后才能加入 |

- 按志愿者的稳定 ID 去重：同一个人分别以姓名、英文名和 ID 出现，也只能添加一次。
- 可以明确选择“加入已匹配的 N 人”，错误项保留供继续修正，不静默丢弃。
- 单次粘贴按拆分、trim、去空后的输入条目数限制 500（去重前）；最终待提交人员也不得超过 500，超出时明确提示拆分。场次总名单使用分页，不静默截断。
- 校验期间显示处理状态；输入改变后旧校验结果失效，保存时再次检查当前名单和权限。

### 2.3 搜索添加与后续补录

- 支持按姓名或志愿者 ID 搜索，结果同时展示部门以区分重名。
- 搜索结果标记“已添加”“待加入”等状态，重复选择时提醒且不增加记录。
- 搜索添加与粘贴录入使用同一个待加入名单，去重规则一致。
- 录入期间始终能看到当前名单与待加入人员，并可移除尚未提交的选择。
- 后续粘贴或搜索默认是追加比对；新名单没有出现的原有人员保持不变，不将粘贴解释为全量覆盖。
- 提交完成显示实际新增人数、重复跳过人数及需要继续处理的项目。

### 2.4 编辑、移除和恢复

- 修改场次类型、日期、时长、内容，同步更新该场次全部有效考勤记录。
- 保存前展示修改内容与影响人数；场次及关联记录在同一事务内更新，失败时全部回滚。
- 从已保存名单中移除人员，即撤销该人本场考勤，对应受训记录不再计入有效统计；历史记录保留。
- 恢复人员时恢复原关联记录，不重复创建；恢复前重新检查人员资格、权限及封档状态，并使用当前场次信息。
- 粘贴或搜索命中已移除人员时显示“曾移除，可恢复”，显式确认恢复，不归类为普通新增，也不静默恢复。
- 移除待加入人员只修改本次草稿，不影响已经保存的数据。
- 个人中心可以查看考勤，修改入口指向场次管理，避免从个人记录页单独修改导致场次与记录不一致。
- 原有受训挂接、取消挂接入口和写接口在迁移完成后停用，不能仅隐藏按钮而留下旧写入通道。

## 3. 普通标签

### 3.1 标签组、标签与关联列表

- 保留“标签组 → 具体标签”的层级，例如“笔译岗位 → 初译、校对”。
- 标签组配置使用中文：名称、说明、单选／多选、必填／选填、是否允许新增标签、适用服务项。
- 关联列表展示姓名、服务项、日期、时长和服务记录编号；每行对应具体服务记录，不能只显示一个人名。
- 分别显示去重人数与有效记录数，避免同一人多条记录造成误解。
- 点击姓名进入志愿者主页，点击记录入口查看对应记录；标签本身提供可直接访问的详情地址。
- 列表支持查找并关联符合条件的已有记录、解除关联；解除关联不删除或修改服务记录。
- 服务记录创建和编辑仍在原有业务入口完成，普通标签不再承担批量考勤功能。

### 3.2 适用服务项

界面将“触发源”命名为“适用服务项”，规则配置在标签组层面，同组标签遵循相同适用范围。

- 复用提交志愿服务的“类别 → 部门 → 服务项”结构，将单选改为多选。
- 支持跨类别、跨部门选择、搜索、已选数量和已选项目汇总，切换类别不丢失选择。
- 显式选择“所有志愿服务项”或“指定服务项”；指定模式至少选择一项，不使用空数组隐式表达两种含义。
- 本模块面向原有志愿服务类别，受训服务项由培训考勤模块处理。
- 选择某个服务项提交记录时，显示适用的标签组供选择；不自动给记录贴上该组全部标签。
- 单选、多选、必填和适用范围由服务端校验，不能只依赖表单限制。
- 对仍适用且必填的标签组，不能直接解除最后一个关联；更换标签以一次原子操作完成。历史不适用关联按第 3.3 节处理。标签删除／停用、组删除、多选改为单选的历史冲突处理，在阶段 0 明确后再开放相应写操作。
- 新建服务记录及保存所选标签应在同一事务内完成，避免记录成功但标签部分失败；代提交待确认记录也应保留合法选择，生效后再计入有效关联列表。
- 修改服务项时重新检查标签适用性，向操作者展示冲突及处理方式，不能静默留下无效的新关联。

### 3.3 历史关联

- 修改标签组适用范围不自动清除历史关联；不再符合范围的历史记录标记“需检查”。
- 新关联严格遵守当前规则，历史保留不能成为新增越界关联的理由。
- 删除或停用服务项时保留历史显示，配置页提示失效项目，不按同名服务项自动替换。
- 旧配置中的空适用范围先核对实际语义，不能直接迁移为“适用所有服务项”并突然在所有提交表单中显示。

## 4. 数据与权限规则

### 4.1 培训数据关系

以下是目标契约，实施时补充真实 Prisma 模型和增量迁移。

| 对象 | 关键职责与约束 |
|---|---|
| 培训场次 | 独立 ID、名称、受训服务项、日期、时长、内容、创建／更新信息及并发版本 |
| 场次参加记录 | 场次 ID、志愿者 ID、有效／已移除状态、对应服务记录；同一场次同一志愿者唯一 |
| 现有服务记录 | 继续承接个人展示、台账和统计；一条受训记录最多属于一个场次，场次是编辑入口 |
| 操作审计 | 记录 Account 操作者、场次、增删人员、信息变更和影响范围 |

- 场次与名单是管理来源，个人受训记录是同步结果，避免双向独立编辑。
- 数据库唯一约束和事务防止并发补录重复入账；服务记录现有去重约束需核验，不得误合并不同场次的合法考勤。
- 场次编辑使用版本检查，避免两人操作互相覆盖；冲突时要求刷新并保留可恢复的输入。
- 补录、移除、恢复也与场次编辑参与同一并发协调机制；必须覆盖“甲改时长、乙同时补录”，确保新记录使用提交时有效的场次信息，而非旧预览数据。预览与提交之间的封档、人员权限变更也需在写入时复核。
- 参加者关联 Volunteer，操作者关联 Account。纯系统 admin 不需要志愿者档案即可管理考勤。
- 现有服务记录提交者、标签关联操作者包含必填 Volunteer 外键；需安排兼容迁移和序列化适配，保留原有归属，不借用受训者身份冒充操作者，也不创建 admin 替身志愿者。

### 4.2 权限与封档

- 培训与标签沿用当前台账权限，不使用论坛圈主／协管员权限。
- 系统 admin 可跨范围管理；录入员沿用现有部门及记录范围限制；标签组配置继续由系统 admin 管理。
- 角色以当前代码为准：`admin` 全局且按既有规则享有封档更正权限，`b_admin` 全局录入但不豁免封档，`a_admin` 为部长、按志愿者所属部门限制，`user` 仅按已有本人记录授权。不能沿用旧文档中 `a_admin ≡ b_admin` 的描述。
- 阶段 0 明确跨部门场次的可见名单、人数口径、空场次归属及人员调部门后的历史管理规则；名单查询与写入不得采用不同部门范围。
- 普通志愿者可查看自己的考勤，不能自行修改或删除；普通标签关联沿用本人记录的现有授权规则。
- 名单搜索、粘贴校验和保存均应用同一权限范围，不能通过名单接口绕过部门限制。
- 修改整个场次要求对所有受影响记录有权限；不能只更新有权限的一部分，却把场次信息改为全体已更新。
- 新增、补录、信息变更、移除、恢复均检查封档；日期变更同时检查旧日期和新日期。系统 admin 按现有规则处理封档更正并留审计。

## 5. 旧数据迁移与切换

1. **盘点并生成报告**：检查现有培训类标签、关联记录的类别、日期、时长、内容、人员重复情况，以及无标签受训记录、一条记录多重关联的情况。
2. **确定场次映射**：不能将所有 `managed` 标签一概视为培训，也不能把一个混有多日期或多类型的标签直接当成单场次。明确且一致的数据建立映射，混合或有歧义的数据列入待处理清单。
3. **备份并演练**：在隔离数据库验证增量迁移、映射结果、总人数／记录数／时长及备份恢复；不重置数据库、不重新 seed。
4. **保留历史**：尽量保留既有服务记录 ID、编号及审计，关联到新场次；迁移不重复创建服务记录，不重复累计时长。脚本支持幂等执行。
5. **完成切换**：核对迁移结果后停用旧培训批量和挂接写入口，旧页面地址提供新入口。普通标签历史关联继续保留；旧培训关联不再作为名单来源。

有歧义数据未解决前，不自动合并或删除；切换期间明确唯一写入口，避免旧标签与新场次同时维护同一批考勤。

回退方案保留新数据与迁移映射；新场次产生后，不能直接回退到只理解旧标签的应用版本。

## 7. 验收清单

- 可先建空场次，独立编辑类型、时长、内容、日期，再录入或补录名单。
- 粘贴识别未匹配、重名、本次重复、已在名单；姓名／ID 指向同一人时正确去重。
- 搜索与粘贴共享待加入名单，添加过程中可见当前名单；重新粘贴不会删除既有人选。
- 并发添加同一人只生成一条有效考勤；失败不会留下半份名单或孤立服务记录。
- 场次编辑同步全部有效记录；移除不计时长，恢复不重复计数，个人中心不可绕过场次单独改写。
- 纯 admin 可管理；录入员部门范围、普通用户权限、封档及跨日期修改边界正确。
