## 🔍 **设计说明**

- **记录状态与操作权限**：
  - **待审核（○）**：自由操作期，可随意修改、删除
  - **已确认（●）**：保护期，修改/删除需申请，等待管理员审核
  - **已拒绝（×）**：修正期，可查看原因、重新提交或删除

- **申请流程设计**：
  - **申请修改**：提交修改内容，生成新的待审核记录，原记录保持
  - **申请删除**：提交删除理由，等待管理员批准
  - **重新提交**：针对已拒绝记录，修改后重新提交审核

- **批量操作权限**：
  - 批量删除：仅限待审核和已拒绝记录
  - 批量申请修改：仅限已确认记录
  - 导出功能：所有状态记录均可导出

---

## 📝 **设计决策与备注**

1. **权限分级设计**：
   - 待审核记录：完全控制（符合实际工作流程）
   - 已确认记录：申请制（确保数据完整性和准确性）
   - 已拒绝记录：修正机会（给予用户改正机会）

2. **申请流程透明化**：
   - 明确展示不同状态的操作权限
   - 申请操作有明确的结果预期
   - 审核流程对用户透明

3. **批量操作优化**：
   - 根据记录状态限制批量操作权限
   - 批量申请功能提高工作效率
   - 导出功能支持数据分析和备份

4. **用户体验考虑**：
   - 清晰的视觉标识（●○×）快速识别状态
   - 操作按钮根据状态动态显示
   - 权限说明帮助用户理解操作限制

5. **扩展性设计**：
   - 申请审核流程可扩展通知机制
   - 批量操作支持更多业务场景
   - 状态标识系统支持更多状态类型

## 📊 **申请流程详细说明**

### **申请修改已确认记录**
1. 用户点击"申请修改"按钮
2. 弹出修改表单（预填原记录内容，可编辑）
3. 用户填写修改理由和修改内容
4. 提交后生成一条"修改申请"记录（待审核状态）
5. 原记录保持"已确认"状态，显示"有修改申请"
6. 管理员审核修改申请
7. 审核通过：更新原记录，保留修改历史
8. 审核拒绝：保持原记录不变，申请记录标记为"已拒绝"

### **申请删除已确认记录**
1. 用户点击"申请删除"按钮
2. 弹出删除理由表单
3. 用户填写删除理由
4. 提交后生成一条"删除申请"记录（待审核状态）
5. 原记录保持"已确认"状态，显示"有删除申请"
6. 管理员审核删除申请
7. 审核通过：标记原记录为"已删除"（逻辑删除）
8. 审核拒绝：保持原记录不变，申请记录标记为"已拒绝"

### **重新提交已拒绝记录**
1. 用户点击"重新提交"按钮
2. 弹出修改表单（预填原记录内容，可编辑）
3. 用户修正问题后重新提交
4. 生成新的待审核记录
5. 原已拒绝记录标记为"已重新提交"

---

> **提示**：请根据记录状态选择相应操作。**已确认**记录的修改和删除需要提交申请，等待管理员审核。**待审核**记录可直接操作。
