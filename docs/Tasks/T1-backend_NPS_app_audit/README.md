## 🎯 核心功能概览

### ✅ 设计原则
- 志愿者状态放宽：离职志愿者也可补录服务
- 复合ID生成策略：`APP-{submitterId}-{seq}` 等，序号永不重置
- 软删除机制：`isActive` 标记，支持数据恢复
- 单条操作优先，验证失败立即返回错误

---

## 📡 API 概览

系统提供以下核心模块接口：

- **申请管理**：提交、预验证、我的申请、撤销申请
- **审核管理**：待审核列表、审核操作、重审与撤回
- **正式服务记录**：查询、统计、导出
- **审计日志**：操作记录查询与分析
- **志愿者管理**：列表、详情、增删改、统计（支持查询参数搜索）
- **健康检查**：`GET /api/health`

> 详细接口请查看 [api.md](./api.md)

## 🗃️ 数据模型

系统包含四个核心数据模型：

| 模型 | 说明 |
|------|------|
| `Volunteer` | 志愿者基本信息与统计字段 |
| `ServiceApplication` | 服务申请缓冲区，记录待审核的变更 |
| `NonProjectService` | 正式服务记录库，含审核历史 |
| `AuditLog` | 完整审计日志，记录所有审核操作 |

> 详细字段定义请查看 [database.md](./database.md)

## 🔄 业务流程

系统遵循“申请 → 审核 → 同步 → 审计”的标准流程：

1. **用户提交申请**（创建/更新/删除）
2. **管理员审核**（通过/拒绝）
3. **数据同步**（写入正式库、更新统计）
4. **审计记录**（记录操作链路）

> 详细流程示例请查看 [operation_flow.md](./operation_flow.md)
